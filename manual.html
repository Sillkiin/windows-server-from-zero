Блок 1

Сервер и маленький офис

Сначала разберёмся, кто за что отвечает.

Что мы собираем

Представь офис из десяти человек. Анне нужны своя учётная запись, рабочий компьютер, папка отдела и принтер. Администратор создаёт эти вещи и определяет, кому что разрешено. Windows Server — операционная система, на которую устанавливают нужные роли: наборы служб для определённой работы.

AD DS ведёт общий каталог пользователей, компьютеров и групп. DNS находит адрес по имени. DHCP выдаёт сетевые настройки. File Server открывает общие папки. GPO раздаёт правила. Это разные задачи: установка одной роли не настраивает остальные автоматически.

Установить роль — как привезти в офис пустой шкаф. Настроить её — собрать полки и определить, что где хранится. Создать пользователя или общую папку — положить конкретный предмет. Служба — работающая в фоне программа; оснастка — окно для управления ею. Закрытое окно управления не останавливает службу.

В основной схеме шлюза нет, интернет не нужен. Все ВМ находятся в одной виртуальной сети. Сеть 192.168.50.0/24 — пример: перед настоящим созданием проверь, что она не пересекается с твоими VPN и сетями. example.test предназначен для примеров; в рабочей организации имя домена планируют заранее, обычно как поддомен принадлежащего ей имени.

Где что добавляется

  1. Роли и компоненты: Server Manager → Manage → Add Roles and Features.
  2. Пользователи, группы и OU: Tools → Active Directory Users and Computers (dsa.msc).
  3. DNS-записи: Tools → DNS (dnsmgmt.msc).
  4. Пул адресов: Tools → DHCP (dhcpmgmt.msc).
  5. Общие папки: File and Storage Services → Shares.
  6. Политики: Tools → Group Policy Management (gpmc.msc).
  7. Службы и журналы: services.msc и eventvwr.msc.

В Server Core этих окон на самом сервере может не быть: им управляют удалённо или командами. На первых шагах используем Desktop Experience и обычный Windows PowerShell 5.1 от имени администратора. Имена кнопок приведены по английскому интерфейсу; русский перевод зависит от выпуска.

Блок 2

Версия, виртуальная машина и установка

Готовим отдельную песочницу для практики.

Какую версию брать

Основной пример — Windows Server 2025 Standard с Desktop Experience. Большинство описанных базовых действий похоже в Windows Server 2022. Выбирай поддерживаемую версию, с которой совместимы приложение, драйверы и резервное копирование. Установка «самой новой» сама по себе не решает совместимость. По карточкам Microsoft: основная поддержка Server 2025 — до ноября 2029, расширенная — до ноября 2034; у Server 2022 соответственно октябрь 2026 и октябрь 2031. На дату этой инструкции Server 2022 уже находится в периоде расширенной поддержки. Точные границы и условия отдельных продуктов/ESU проверяют в карточках жизненного цикла.

Standard и Datacenter — редакции с разными возможностями и правами виртуализации. Для этой лаборатории обычно достаточно Standard. Лицензии Windows Server, клиентские CAL и RDS CAL — разные позиции; учебный пример не рассчитывает лицензионную стоимость.

Desktop Experience содержит привычный рабочий стол. Server Core обходится без полного рабочего стола. В современных выпусках превратить Core в Desktop Experience добавлением галочки нельзя: требуется новая установка. Поэтому название варианта проверяют до нажатия Install.

Официальная Evaluation-версия Server 2025 рассчитана на 180 дней; это временный вариант для оценки, с условиями Microsoft. Страница загрузки требует интернет-активацию в первые 10 дней, поэтому её нужно организовать на подготовительном этапе до окончательной изоляции. Не строй рабочий домен на обещании «потом просто активировать»: для контроллера на Evaluation действуют ограничения преобразования в коммерческую редакцию.

Подготовка лаборатории

Практический старт для хоста с достаточными ресурсами: DC1 — 2 vCPU, 4 ГБ RAM, диск 80 ГБ; FS1 — 2 vCPU, 4 ГБ RAM, системный диск 80 ГБ и отдельный учебный диск; PC1 — ресурсы по требованиям гостевой Windows. Это удобные учебные значения, не официальные минимумы. Проверяй свободную память и место с учётом снимков.

  1. В уже установленном гипервизоре создай отдельную сеть только между учебными ВМ. В Hyper-V это Private switch; в VMware — LAN Segment либо отдельная host-only сеть с выключенным DHCP гипервизора. Host-only может давать доступ к хосту — это учитывают при изоляции.
  2. Подключи все три ВМ к этой сети. Не подключай учебный DHCP к Bridge/External. В основной схеме нет NAT и шлюза: так второй DHCP не вмешается в домашнюю сеть.
  3. Скачай ISO с официальной страницы Microsoft. Создание ВМ и установка гипервизора здесь описаны как действия для тебя; этот учебник их не выполняет.
  4. Создай ВМ DC1 и подключи ISO. Выбери язык, Standard (Desktop Experience), пользовательскую установку и пустой виртуальный диск нужной ВМ.
  5. Дождись копирования файлов и перезагрузки. Установи собственный длинный пароль Administrator, проверь раскладку клавиатуры. В консоли ВМ Ctrl+Alt+Del отправляют через меню гипервизора.
  6. Установи гостевые средства интеграции из доверенного источника. Сделай начальный снимок до создания домена, чтобы можно было повторить лабораторию.

Для получения обновлений можно временно организовать отдельный контролируемый интернет-доступ до включения учебного DHCP, затем вернуться к основной изолированной схеме. Конкретный NAT и его адреса зависят от гипервизора. Не подставляй придуманный шлюз в основную схему.

Как проверить

Открой PowerShell на новой ВМ:

Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsBuildNumber
Get-NetIPConfiguration

Первая команда читает выпуск и сборку. Вторая показывает сетевые интерфейсы. На этом шаге они ничего не устанавливают. Если выбрана не та редакция или не тот тип интерфейса, исправить это проще до настройки домена. Снимок ВМ удобен для учебного повтора, но не заменяет резервную копию рабочего контроллера AD.

Блок 3

Первый запуск: имя, адрес и время

Делаем сервер предсказуемым.

Что настроить до домена

На DC1: имя DC1, IPv4 192.168.50.10, маска 255.255.255.0, шлюз пустой, DNS 192.168.50.10. До установки DNS сервер ещё не будет отвечать на запросы — это ожидаемая промежуточная стадия изолированной лаборатории. На FS1: имя FS1, адрес 192.168.50.20, та же маска и DNS 192.168.50.10.

Адрес контроллера должен быть стабильным. Не назначай два одинаковых адреса. Публичный DNS вроде 8.8.8.8 не умеет находить внутренние записи AD; не ставь его вторым DNS на доменных клиентах «для надёжности». Вторым обычно указывают другой внутренний DNS с нужной зоной, когда он действительно развёрнут.

Мышкой

  1. Server Manager → Local Server → Computer name → Change. На DC1 введи DC1, подтверди и перезагрузи эту ВМ. Имя меняют до повышения до контроллера.
  2. В Local Server → Ethernet открой нужный адаптер → Properties → Internet Protocol Version 4 → Properties. Поставь учебные IPv4, маску и DNS. На этом шаге не отключай IPv6.
  3. Проверь часовой пояс и фактическое время. После создания домена клиенты получают время по доменной иерархии; источник для корневого PDC Emulator планируют отдельно. В изоляции часы могут постепенно расходиться.
  4. Посмотри состояние Windows Firewall, защиты, активации и обновлений. Сетевые правила открывают под конкретную службу, а не отключением всех профилей.

Командами на DC1, локальная консоль, администратор

Сначала найди индекс нужного интерфейса. 12 ниже — только пример. Не копируй его без проверки.

Get-NetAdapter
Get-NetIPConfiguration
Rename-Computer -NewName 'DC1'
Restart-Computer

Rename-Computer меняет имя; Restart-Computer сразу запускает перезагрузку. Выполняй после сохранения работы. После входа проверь имя командой hostname.

Если на адаптере уже есть адреса и шлюзы, сначала разберись с ними в графическом окне. Следующий пример подходит для подготовленного интерфейса без конфликтующего ручного IPv4:

New-NetIPAddress -InterfaceIndex 12 -IPAddress 192.168.50.10 -PrefixLength 24
Set-DnsClientServerAddress -InterfaceIndex 12 -ServerAddresses 192.168.50.10
Get-NetIPConfiguration
Get-TimeZone
w32tm /query /status

Первая команда назначает статический IPv4 и может отключить DHCP на этом интерфейсе; вторая меняет DNS-клиент. Это изменения конфигурации. В удалённом сеансе смена адреса может оборвать связь, поэтому лабораторный шаг делай через консоль ВМ. Если ошибся — верни записанные прежние значения через эту консоль. Не отключай сетевые адаптеры наугад.

Проверка: hostname даёт DC1; Get-NetIPConfiguration показывает ожидаемые адрес, префикс и DNS, без придуманного шлюза. На FS1 повтори с его именем и адресом. Недоступность интернета в нашей изолированной схеме — ожидаемый результат, а не признак сломанного DNS.

Блок 4

Домен и первый контроллер

Создаём общий список сотрудников и компьютеров.

Что такое AD, домен и контроллер

Active Directory Domain Services (AD DS) — служба каталога. Домен — область с общими учётными записями и правилами. Контроллер домена (DC) — сервер с каталогом AD. Лес — верхняя структура AD; для нашего одного домена создаётся один лес. Это не то же самое, что имя сайта, рабочая группа или Microsoft Entra ID.

Для новой лаборатории нужен DC1 с постоянным адресом, правильным временем, административным входом и заранее выбранным именем. Существующий рабочий домен не пересоздают командой создания нового леса. Для рабочего офиса планируют минимум два контроллера на независимых точках отказа и резервное копирование; один DC здесь — учебное упрощение.

Установить и настроить мышкой на DC1

  1. Server Manager → Manage → Add Roles and Features → Role-based or feature-based installation.
  2. Выбери DC1, отметь Active Directory Domain Services, согласись добавить требуемые средства управления, нажми Install.
  3. После завершения нажми флажок уведомлений → Promote this server to a domain controller.
  4. Для новой лаборатории выбери Add a new forest, имя ad.example.test.
  5. Оставь DNS Server и Global Catalog. Функциональные уровни выбирай совместимыми с запланированными контроллерами; значения по умолчанию прочитай, а не переключай наугад. Это не номер установленной ОС.
  6. Задай отдельный надёжный пароль DSRM для режима восстановления каталога; сохрани его вне этой страницы. Это не пароль обычного сотрудника.
  7. В изолированной тестовой зоне предупреждение о невозможности создать DNS delegation в родительской зоне может быть ожидаемым. Не игнорируй остальные проверки автоматически.
  8. Проверь короткое имя LAB, пути базы и SYSVOL, дождись проверки prerequisites, нажми Install. DC1 перезагрузится.

То же через PowerShell, DC1, администратор

Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
Install-ADDSForest -DomainName 'ad.example.test' -DomainNetBIOSName 'LAB' -InstallDNS

Вторая команда создаёт новый лес, запрашивает пароль DSRM и подтверждение, затем обычно перезагружает сервер. Не добавляй -Force и обход предварительных проверок ради исчезновения вопросов. Команды предназначены для чистой лаборатории, не для «починки» существующего AD.

Что должно появиться

После перезагрузки входи доменной административной учётной записью, например LAB\Administrator. В меню Tools доступны AD Users and Computers и DNS. Читай состояние:

Get-ADDomain
Get-ADDomainController -Filter *
Get-Service NTDS, DNS, Netlogon
Get-SmbShare -Name SYSVOL, NETLOGON
dcdiag /test:dns

У Get-ADDomain ожидаем домен ad.example.test; в списке контроллеров — DC1. SYSVOL хранит в том числе файлы политик. Вывод dcdiag разбирают по конкретной проверке: отсутствие внешнего DNS в изоляции не равнозначно повреждению каталога.

Повышение до DC — важное изменение архитектуры. Его штатно отменяют понижением контроллера после проверки ролей и зависимостей. Не удаляй NTDS и SYSVOL руками. Для полного учебного повтора проще вернуть согласованную чистую лабораторию; рабочие контроллеры не откатывают произвольным снимком как обычный документ.

Блок 5

DNS: имена вместо запоминания адресов

Добавляем запись и проверяем, кто ответил.

Какие записи нужны

A связывает имя с IPv4, AAAA — с IPv6, CNAME задаёт псевдоним другого имени, PTR помогает найти имя по адресу, SRV сообщает о местоположении службы, например контроллера домена. Зона — часть справочника, за которую отвечает сервер. В AD важны не только записи DC1, но и служебные SRV.

На DC1 мастер AD обычно уже создал зону ad.example.test. Не создавай вместо неё вторую одноимённую зону без понимания. Для доменных зон используют безопасные динамические обновления и корректные права. Учебное добавление A-записи не заменяет ввод FS1 в домен.

Добавить понятное имя файлового сервера

  1. На DC1 открой Tools → DNS → DC1 → Forward Lookup Zones → ad.example.test.
  2. Правой кнопкой по зоне → New Host (A or AAAA).
  3. Name: files, IP: 192.168.50.20. Получится files.ad.example.test.
  4. Флажок Create associated PTR record имеет смысл, если уже существует подходящая обратная зона. Отсутствие PTR само по себе не ломает каждое обращение по имени.
  5. На PC1 или FS1 проверь именно ответ внутреннего DNS:
Resolve-DnsName files.ad.example.test -Server 192.168.50.10
Resolve-DnsName -Type SRV _ldap._tcp.dc._msdcs.ad.example.test -Server 192.168.50.10
Get-DnsClientServerAddress

Первая команда должна получить учебный IPv4 FS1. Вторая ищет контроллеры через SRV. Третья показывает, на какие DNS настроен клиент. Наличие A-записи не создаёт саму общую папку и не открывает доступ. Для первого SMB-подключения используй основное имя \\FS1\Accounting: псевдонимы SMB могут требовать отдельной настройки имён и Kerberos/SPN, поэтому не считай любой DNS-псевдоним готовым файловым адресом.

Командой на DC1 ту же A-запись добавляют так:

Add-DnsServerResourceRecordA -ZoneName 'ad.example.test' -Name 'files' -IPv4Address 192.168.50.20

Если запись уже существует с тем же именем, сначала прочитай её, не создавай дубликаты наугад. Исправление — проверить нужную запись в зоне и изменить либо удалить только ошибочную запись, учитывая кэш клиентов.

Внутренние и внешние имена

Доменный клиент спрашивает внутренний DNS. Для внешних имён внутренний DNS при наличии сетевого выхода может использовать forwarders или root hints. Forwarder задают на DNS-сервере, а не вторым публичным DNS на каждом доменном ПК. В основной лаборатории интернета нет, поэтому внешние запросы могут не разрешаться. ipconfig /flushdns очищает клиентский кэш, но не исправляет неправильный адрес DNS и отсутствующую запись.

Проверяй по слоям: имя разрешилось → адрес доступен по нужному TCP-порту → служба ответила → пользователь прошёл проверку доступа. ping не заменяет эти четыре проверки.

DHCP: выдаём компьютерам сетевые настройки

Создаём пул, DNS-опции и резервирование.

Что именно выдаёт DHCP

Клиент обычно получает IPv4, маску, срок аренды, адрес DNS, доменный суффикс и при наличии маршрутизатора — шлюз. Scope (область) содержит диапазон выдачи. Exclusion (исключение) вырезает адреса из диапазона. Reservation (резервирование) закрепляет адрес за идентификатором конкретного клиента. Lease (аренда) — временная выдача адреса.

Перед включением проверь, что в учебном сегменте нет другого DHCP, в том числе DHCP гипервизора. Авторизация в AD — проверка доверия к Windows DHCP в доменной среде; она не создаёт пул и не блокирует любой посторонний DHCP в сети.

Настроить на DC1 мышкой

  1. Add Roles and Features → DHCP Server → Install. Затем Complete DHCP configuration: заверши посленастроечные действия и авторизуй сервер с нужными правами.
  2. Tools → DHCP → DC1 → IPv4 → New Scope. Имя: Office-Lab.
  3. Диапазон: 192.168.50.100–192.168.50.150, маска 255.255.255.0. Адреса .10 и .20 уже вне пула и не нуждаются в исключении внутри него.
  4. Срок аренды оставь осмысленным для лаборатории. В Router опции шлюз не добавляй, потому что в основной схеме маршрутизатора нет.
  5. В DNS Domain Name укажи ad.example.test, DNS Server — 192.168.50.10.
  6. Активируй область, убедись в авторизации и рабочей службе. На PC1 включи автоматическое получение IPv4 и DNS.

Основные команды, DC1, администратор

Install-WindowsFeature DHCP -IncludeManagementTools
Add-DhcpServerInDC -DnsName 'DC1.ad.example.test' -IPAddress 192.168.50.10
Add-DhcpServerv4Scope -Name 'Office-Lab' -StartRange 192.168.50.100 -EndRange 192.168.50.150 -SubnetMask 255.255.255.0 -State InActive
Set-DhcpServerv4OptionValue -ScopeId 192.168.50.0 -DnsDomain 'ad.example.test' -DnsServer 192.168.50.10
Set-DhcpServerv4Scope -ScopeId 192.168.50.0 -State Active
Get-DhcpServerInDC
Get-DhcpServerv4Lease -ScopeId 192.168.50.0

Команды конфигурации выполняют после посленастроечного завершения роли; они показывают основные объекты и не заменяют проверку служебных групп, привязок интерфейса и диагностических сообщений. Область сначала создаётся неактивной, чтобы успеть проверить опции. На PC1 после сохранения работы можно запросить новую аренду: ipconfig /renew, затем прочитать ipconfig /all. На удалённой рабочей машине принудительное обновление адреса может прервать связь.

Закрепить адрес принтера

В Scope → Reservations → New Reservation указывают имя, свободный адрес внутри области и реальный идентификатор клиента, обычно MAC. Узнай его в настройках принтера или действующей аренде. Не копируй MAC другого устройства. После резервирования клиент должен заново получить аренду; оно не переименовывает устройство и не устанавливает драйвер.

Адрес 169.254.x.x часто означает, что Windows назначила IPv4 сама, не получив подходящую аренду. Проверяй виртуальный коммутатор, службу, активность области, свободные адреса и правила; это подсказка, а не доказанная единственная причина. Если DHCP находится в другом сегменте, нужен маршрутизатор с DHCP relay — в нашей одной сети он не требуется. При ошибке сначала деактивируй учебную область, затем исправляй её параметры.

Блок 7

OU, пользователи и группы

Добавляем сотрудника и выдаём доступ через группы.

Три разных объекта

Пользователь представляет человека или отдельную служебную задачу. Группа безопасности объединяет учётные записи для назначения прав. OU (организационная единица) содержит объекты для организации, делегирования и применения GPO. Перемещение Анны в OU Accounting само по себе не разрешает папку Accounting. Для папки используют группу и её разрешения.

В одном домене удобно правило AGDLP: Accounts → Global groups → Domain Local groups → Permissions. Учётку Анны включим в GG_Accounting, эту группу — в DL_Accounting_Modify, а последней выдадим право на папку. Слова Global и Domain Local — области действия групп. Для сложных многодоменных сред схема может отличаться; сначала освоим эту.

Добавить мышкой на DC1

  1. Tools → Active Directory Users and Computers (dsa.msc). Раскрой ad.example.test.
  2. Правой кнопкой по домену → New → Organizational Unit, имя Office. Оставь защиту от случайного удаления. Внутри создай Users, Computers, Groups, Servers.
  3. В Office/Users → New → User: имя Анна, логин anna, UPN anna@ad.example.test. UPN выглядит как почта, но создание почтового ящика не выполняет.
  4. Назначь собственный временный пароль и User must change password at next logon. Не включай Password never expires обычному сотруднику ради удобства. Временный пароль передают по принятому защищённому каналу.
  5. В Office/Groups создай GG_Accounting: Global, Security. Создай DL_Accounting_Modify: Domain Local, Security.
  6. Открой свойства GG_Accounting → Members → Add → anna. Затем в члены DL_Accounting_Modify добавь GG_Accounting.

Команды на DC1, с правами на нужные OU

Это пример для новой пустой учебной структуры. Если объекты уже существуют, сначала проверь их и не выполняй создание повторно.

$base = 'DC=ad,DC=example,DC=test'
New-ADOrganizationalUnit -Name 'Office' -Path $base
$office = 'OU=Office,' + $base
New-ADOrganizationalUnit -Name 'Users' -Path $office
New-ADOrganizationalUnit -Name 'Computers' -Path $office
New-ADOrganizationalUnit -Name 'Groups' -Path $office
New-ADOrganizationalUnit -Name 'Servers' -Path $office
$users = 'OU=Users,' + $office
$groups = 'OU=Groups,' + $office
$pw = Read-Host 'Временный пароль Анны' -AsSecureString
New-ADUser -Name 'Анна Иванова' -SamAccountName 'anna' -UserPrincipalName 'anna@ad.example.test' -Path $users -AccountPassword $pw -Enabled $true -ChangePasswordAtLogon $true
New-ADGroup -Name 'GG_Accounting' -GroupScope Global -GroupCategory Security -Path $groups
New-ADGroup -Name 'DL_Accounting_Modify' -GroupScope DomainLocal -GroupCategory Security -Path $groups
Add-ADGroupMember -Identity 'GG_Accounting' -Members 'anna'
Add-ADGroupMember -Identity 'DL_Accounting_Modify' -Members 'GG_Accounting'
Get-ADGroupMember 'GG_Accounting'
Get-ADGroupMember 'DL_Accounting_Modify'

Read-Host -AsSecureString запрашивает пароль без открытого текста в скрипте. Сохранять настоящие пароли в учебник не нужно. После изменения групп Анне может понадобиться полный выход и новый вход: уже выданный токен доступа не всегда обновляется мгновенно.

Проверка: объект существует в нужной OU, учётка включена, членство соответствует задаче. Обычному сотруднику не нужна Domain Admins. Если ошибся в правах, исправь членство нужной группы, не удаляй пользователя с документами «для начала заново». Для увольнения сначала блокируют учётку по процедуре, а не сразу удаляют все данные.

Официальные источники: Группы безопасности AD · PowerShell: New-ADUser
Блок 8

Вводим компьютер и сервер в домен

Компьютер должен найти домен и получить свою учётную запись.

Что проверить заранее

PC1 должен работать на редакции Windows с поддержкой присоединения к AD, например Pro, Enterprise или Education; обычная Home не подходит. Имя компьютера уникально, DNS указывает на DC1, время не расходится существенно, контроллер доступен. FS1 вводится в тот же домен как рядовой сервер, без установки AD DS.

Вход локальным администратором на PC1 и права присоединения в домене — разные полномочия. В организации используют делегированную учётку на нужную OU, а не раздают всем Domain Admins. При повторном использовании существующей учётной записи компьютера действуют дополнительные проверки владельца и защиты domain join; не отключай их, чтобы спрятать ошибку.

На PC1 мышкой

  1. Проверь ipconfig /all: внутренний DNS — 192.168.50.10.
  2. Открой sysdm.cpl → Computer Name → Change → Member of: Domain.
  3. Введи ad.example.test. При запросе укажи учётную запись, которой разрешено добавление этого компьютера.
  4. Дождись сообщения об успешном присоединении и перезагрузи PC1. Само сообщение ещё не проверяет вход Анны.
  5. На экране входа выбери Other user и введи LAB\anna либо anna@ad.example.test. Для входа локально используй PC1\имя или .\имя.
  6. Для первого изменения временного пароля Анны удобнее консоль PC1. Вход через RDP с NLA и требованием смены пароля может требовать отдельного маршрута смены пароля.

Командой с PC1, локальный администратор

OU Office/Computers должна уже существовать. Команда меняет членство компьютера и перезагружает его после подтверждённой операции:

Add-Computer -DomainName 'ad.example.test' -OUPath 'OU=Computers,OU=Office,DC=ad,DC=example,DC=test' -Credential (Get-Credential) -Restart

Не вводи пароль прямо в строку. FS1 аналогично направляют в OU=Servers,OU=Office,DC=ad,DC=example,DC=test. При вводе через графическое окно компьютер может оказаться в стандартном контейнере Computers — позже перемести его объект в Office/Computers через ADUC. Это нужно для OU-политик.

Проверка на PC1

whoami
Get-CimInstance Win32_ComputerSystem | Select-Object Name, Domain, PartOfDomain
nltest /dsgetdc:ad.example.test

PartOfDomain=True подтверждает членство машины. whoami в сеансе Анны должен показывать lab\anna, а не локальную учётку. nltest ищет контроллер. Для проверки доверительного канала рядового ПК администратор может выполнить Test-ComputerSecureChannel без -Repair; это не универсальная проверка контроллера домена.

Если не получается: сначала DNS и SRV, затем время, доступность служб и права присоединения. Не «лечи» это созданием нового леса. Перед выводом из домена убедись, что есть рабочая локальная административная учётка, сохранены нужные данные и ключи; доменный профиль и локальный профиль не являются одним и тем же.

Блок 9

Диски, тома и место

Добавляем диск данных и не форматируем чужое.

Что нужно различать

Виртуальный диск находится в файлах гипервизора, а гостевая Windows видит его как устройство. Раздел задаёт часть диска, файловая система организует данные, буква вроде D: — точка доступа к тому. Файлы виртуальных дисков на хосте и разделы внутри ВМ — разные уровни. Thin provisioning не обещает бесконечное место: заполниться может и гостевой том, и диск хоста.

RAID и зеркала повышают доступность при части аппаратных отказов. Они не возвращают вчерашний удалённый файл и не защищают от шифрования с действующими правами. Снимок, теневая копия, реплика и резервная копия тоже имеют разные свойства.

Добавить учебный диск на FS1

  1. Через настройки нужной ВМ FS1 добавь новый пустой виртуальный диск, например 40 ГБ. Перед операцией проверь имя ВМ и доступное место хоста.
  2. Внутри FS1 открой diskmgmt.msc. Найди новый диск по размеру, номеру и состоянию. Системный диск с C: не трогай.
  3. Только новый пустой диск инициализируй как GPT. Если на диске есть данные или неизвестная разметка, остановись и выясни происхождение — «не видит Windows» не означает «можно стереть».
  4. На нераспределённом пространстве → New Simple Volume, размер, свободная буква D:, файловая система NTFS, метка Data-Lab. Если D: занята, выбери другую букву и последовательно измени учебные пути.
  5. После форматирования создай D:\Shares, затем учебную папку Accounting. Форматирование уничтожает прежнюю файловую структуру выбранного тома; это не способ исправления доступа к папке.

Прочитать состояние без изменения разметки

Get-Disk | Select-Object Number, FriendlyName, PartitionStyle, OperationalStatus, Size
Get-Volume | Select-Object DriveLetter, FileSystemLabel, FileSystem, Size, SizeRemaining
Get-Partition

Эти команды помогают сопоставить устройство, том и букву. Автоматические Clear-Disk, Initialize-Disk и Format-Volume в тренажёре не предлагаются для исполнения: для новичка важнее сначала уверенно опознать правильный диск.

Что контролировать

На FS1 — свободное место, ошибки диска и резервное копирование; на хосте — место для виртуальных дисков и растущих checkpoints. Для ограничения и учёта данных можно установить File Server Resource Manager (FSRM): квоты, уведомления, отчёты. Квота не является резервной копией и может мешать записи, если достигнут лимит.

Теневые копии могут облегчить восстановление прошлой версии файла, но на том же хранилище остаются общей точкой отказа. Перед расширением тома проверь копию и поддержку операции; место «на хосте» не увеличивает гостевой том автоматически. Перед отключением диска найди приложения, публикации и резервные задания, которые используют его букву или путь.

Блок 10

Общие папки и права

Разбираемся с двумя замками: SMB и NTFS.

Две проверки доступа

SMB share permissions проверяются при сетевом обращении к общей папке. NTFS permissions действуют на файлы и папки файловой системы, в том числе локально. Для доступа по сети действие должно быть разрешено на обоих уровнях. Share Change + NTFS Read даёт чтение, но не запись. Это упрощение для обычных Allow без сложных наследований и Deny.

Не раздавай Everyone Full Control как стандартное решение. Права Read позволяют читать; NTFS Modify обычно включает создание, изменение и удаление; Full Control дополнительно позволяет менять разрешения и владельца. Явные Deny, наследование и несколько групп могут усложнить итог — смотри Effective Access для конкретной учётной записи.

На FS1 подготовить папку

FS1 уже введён в домен. В разделе дисков описано создание отдельного учебного тома D:. Если его пока нет, сначала подготовь том; не используй D:, занятый DVD, как будто это диск данных.

  1. Создай D:\Shares\Accounting.
  2. Properties → Security → Advanced. Прочитай унаследованные права. Для выделенного учебного корня при необходимости отключи наследование с преобразованием записей, затем убери только ненужные широкие записи доступа. Сохрани SYSTEM и административный доступ.
  3. Добавь LAB\DL_Accounting_Modify с Modify, применением к этой папке, подпапкам и файлам. Для группы только чтения создай отдельную группу и Read & execute.
  4. Server Manager → File and Storage Services → Shares → Tasks → New Share → SMB Share — Quick. Путь тот же, имя Accounting.
  5. В разрешениях общего доступа задай группе отдела Change, администраторам — требуемый полный доступ. Проверь итоговые права обоих уровней. Access-based enumeration может скрывать недоступные элементы, но не заменяет ACL.

Пример создания самой публикации SMB в PowerShell на FS1, когда папка и NTFS уже настроены:

New-SmbShare -Name 'Accounting' -Path 'D:\Shares\Accounting' -ChangeAccess 'LAB\DL_Accounting_Modify'
Get-SmbShareAccess -Name 'Accounting'
icacls 'D:\Shares\Accounting'

New-SmbShare публикует путь, а не автоматически исправляет все NTFS-права. icacls без параметров изменения читает ACL. В диалоге Security → Advanced → Effective Access проверь Анну; сетевой доступ дополнительно зависит от SMB-публикации.

Проверить с PC1 как Анна

Открой **\\FS1\Accounting. Создай учебный текстовый файл, измени его и удали только этот тестовый файл**. Затем проверь пользователя без группы: доступа к папке быть не должно. Если группа менялась, полностью выйди и войди снова. Успех под Domain Administrator не проверяет обычного сотрудника.

На клиенте можно читать:

Resolve-DnsName FS1.ad.example.test
Test-NetConnection FS1.ad.example.test -Port 445
whoami /groups
net use

DNS, порт 445, членство и открытие файла — отдельные факты. Windows может держать существующий SMB-сеанс с другими учётными данными; не удаляй все сетевые подключения без разбора. Исправление прав начинай с записи текущих ACL и конкретной ошибки. Публикацию можно снять без удаления файлов, но это отключит пользователей; удаление публикации и удаление данных — разные действия.

Блок 11

Групповые политики

Настройку один раз описываем, затем применяем к нужным объектам.

Как политика добирается до компьютера

GPO — объект с настройками. Link — привязка к сайту, домену или OU. Политика содержит отдельные разделы Computer Configuration и User Configuration. Компьютерную часть связывают с расположением объекта компьютера, пользовательскую — с расположением пользователя; loopback — отдельный продвинутый режим, а не поведение по умолчанию.

Обычный контейнер Computers в корне домена не является OU для прямой привязки GPO. Мы создали OU=Computers,OU=Office,... именно как OU. Наличие группы с таким именем не заменяет OU. Security Filtering и WMI filters дополнительно ограничивают применение; чтение GPO и Apply Group Policy тоже имеют значение.

Первая понятная политика: сообщение перед входом

  1. На DC1 открой Group Policy Management (gpmc.msc). Найди Forest → Domains → ad.example.test → Office → Computers.
  2. Убедись в ADUC, что объект PC1 действительно находится в этой OU.
  3. Правой кнопкой по OU → Create a GPO in this domain, and Link it here. Назови LAB-Logon-Notice.
  4. Edit → Computer Configuration → Policies → Windows Settings → Security Settings → Local Policies → Security Options.
  5. Настрой Interactive logon: Message title for users attempting to log on и Message text.... Для лаборатории текст: «Учебный компьютер».
  6. На PC1 от администратора выполни gpupdate /force. Затем проверь результат политик и новый вход/экран входа. Сохрани работу перед выходом.
gpupdate /force
gpresult /r
gpresult /h "$env:TEMP\gpresult.html"

gpupdate запрашивает обновление, но не гарантирует применение любой настройки: некоторые требуют выхода или перезапуска. gpresult показывает фактическое применение; для полного отчёта компьютерной части нужны соответствующие права. HTML сохраняется в TEMP — это запись диагностического файла, а не изменение самой GPO.

Подключить сетевой диск пользователям

Отдельная GPO с привязкой к Office/Users: User Configuration → Preferences → Windows Settings → Drive Maps → New → Mapped Drive. Action — Update, Location — \\FS1\Accounting, буква — свободная, например P:. Через Item-level targeting можно выбрать группу отдела. Сопоставление диска не выдаёт права на папку: SMB и NTFS всё равно проверяются.

Если не применяется

Проверяй объект и OU → link включён → нужная часть GPO включена → фильтры и права → доступность DC/DNS/SYSVOL → время обновления и отчёт. Порядок обычно Local, Site, Domain, OU; наследование, enforced, block inheritance и фильтры могут изменить результат. Не начинай с Enforced и не делай все политики на корне домена.

Доменные пароли — отдельный случай: обычная password policy для доменных учёток применяется на уровне домена; политика, привязанная только к OU пользователей, не задаёт им индивидуальные доменные пароли. Для разных требований существуют fine-grained password policies. Перед изменением экспортируй/сохрани GPO и начни с тестовой OU. Откат: выключи именно тестовую link либо верни настройку; предпочтения могут оставлять созданные объекты после снятия политики, поэтому проверяй фактическое состояние.

Блок 12

Резервное копирование и восстановление

Проверяем, что получится вернуть, а не только что задание зелёное.

До выбора кнопок

RPO — сколько последних изменений допустимо потерять. RTO — за какое время нужно восстановить работу. Если копия раз в сутки, обещать потерю максимум пяти минут нельзя. Определи, что копировать: файлы FS1, конфигурации приложений и баз, состояние системы DC, данные гипервизора и ключи восстановления.

Правило 3–2–1 помогает начать: несколько копий, разные носители, одна отдельно от площадки. Практически также нужна защищённая offline/immutable копия, отдельные полномочия и проверка восстановления. Копия на том же диске, доступная тем же администратором и шифровальщиком, — слабая защита.

Учебный файловый backup на FS1

  1. Добавь Windows Server Backup через Add Roles and Features → Features. Команда: Install-WindowsFeature Windows-Server-Backup.
  2. Подготовь отдельное целевое хранилище. Его настройка может выделять или форматировать носитель — внимательно прочитай мастер. Не выбирай диск с единственными данными.
  3. Открой wbadmin.msc → Local Backup → Backup Once для первой проверки. Выбери Custom и учебный каталог D:\Shares либо согласованный набор томов.
  4. Выбери подходящий отдельный destination, дождись завершения и прочитай результат задания. При сетевом назначении проверь правила хранения версий и доступ: новое задание может ограничивать сохранение старых версий в зависимости от способа назначения.
  5. Создай в исходной папке тестовый файл, выполни копию, затем Recover → Files and Folders восстанови его в другой каталог, чтобы сначала сравнить содержимое и права.
  6. Когда ручная проба понятна, настрой Backup Schedule, уведомления об ошибках и контроль возраста последней успешной копии.

Команда чтения списка версий на том сервере, где настроены соответствующие копии:

wbadmin get versions

Список версий не доказывает, что любой файл или весь сервер восстановятся. Отдельно проверяют доступность целевого хранилища, дату, состав, целостность и восстановление. Если список пуст, выясни, какой каталог копий и какой продукт реально используются; это не доказательство отсутствия любых внешних копий.

Для контроллера домена

Нужны поддерживаемое AD-aware резервное копирование и план восстановления System State / состояния системы либо полного сервера по выбранной технологии. Включи компонент Windows Server Backup на DC1, в custom-наборе мастера проверь наличие System State и назначение на отдельный носитель. Файловое копирование C:\Windows\NTDS не заменяет такую копию. Полное восстановление AD, authoritative/non-authoritative restore и восстановление леса выполняют по отдельному плану с DSRM и изоляцией.

Второй контроллер помогает пережить отказ первого, но реплицирует и часть ошибок: он не заменяет резервную историю. Снимок работающего DC не объявляют универсальным backup; безопасное восстановление виртуального контроллера зависит от поддержки платформы и процедур AD.

Контрольный протокол

Запиши дату, сервер, backup-набор, место хранения, последнюю версию, восстановленный объект, время восстановления и результат сравнения. Для БД и приложений уточни VSS/application consistency и собственные процедуры продукта. Настрой уведомление об ошибке, иначе «задание существует» может месяцами скрывать отсутствие новых копий. Удалять старые копии можно только по согласованной политике хранения после проверки новых.

Блок 13

Удалённое управление и защита

Управляем сервером отдельной административной учёткой.

Сначала раздели роли людей

Анне для документов не нужны Domain Admins. Администратору полезны две учётки: обычная для повседневной работы и отдельная привилегированная для управления. Права выдаются под задачу, по возможности через делегирование. Сервисам не назначают Domain Admin и «никогда не истекающий общий пароль» по привычке; для поддерживаемых служб рассматривают gMSA.

Windows LAPS помогает управлять разными локальными административными паролями на поддерживаемых устройствах. Внедрение требует настройки хранения, прав чтения и политики; установка компонента не означает, что пароли уже защищённо сохраняются. Для доменных контроллеров есть свои особенности, включая DSRM.

RDP для администратора

  1. На FS1 Server Manager → Local Server → Remote Desktop → Enable. Сохрани требование Network Level Authentication (NLA).
  2. Добавь только нужных администраторов/делегированных операторов. Для рядового сервера локальная группа Remote Desktop Users и права входа могут участвовать в разрешении; Deny log on through Remote Desktop Services перекрывает разрешение.
  3. В Windows Defender Firewall with Advanced Security проверь включённые правила Remote Desktop, профили и область удалённых адресов. Разрешай управление из административной сети/VPN.
  4. С административного компьютера проверь TCP 3389, затем подключись через mstsc по основному имени сервера. Предупреждение о сертификате разбирай по имени, издателю и ожидаемой машине; не превращай привычку «всегда принять» в правило.
Test-NetConnection FS1.ad.example.test -Port 3389

Открытый порт доказывает только TCP-доступность. Он не подтверждает правильный пароль, права входа и успешную RDP-сессию. В изолированной сети подключение возможно только с устройства, которое действительно подключено к ней; с домашней сети без маршрута оно не появится само.

Другие способы

RSAT на административном ПК позволяет открывать ADUC, DNS и GPMC без постоянного входа на DC. PowerShell Remoting/WinRM подходит для командного управления, но требует аутентификации, правил и доверенной модели подключения. Не добавляй TrustedHosts=* и не включай Basic без защиты как универсальный рецепт. Windows Admin Center — отдельный инструмент, который развёртывают и защищают отдельно.

Два одновременных административных RDP-сеанса Windows Server предназначены для администрирования, а не бесплатной терминальной работы всех сотрудников. Для многопользовательских рабочих столов нужны RDS-роли и соответствующее лицензирование.

Не публикуй 3389 или SMB 445 напрямую в интернет. Для внешнего администрирования проектируют VPN либо соответствующий защищённый шлюз, MFA и ограничения источников. Включённый firewall с точными правилами — нормальная работа, отключение всех профилей — не проверка решения.

Проверка защиты: отдельные учётки, минимальные группы, доступ только от нужных адресов, работа NLA, журналы входа, актуальные копии. Перед изменением удалённого доступа обеспечь консольный способ вернуться: ошибочное правило может закрыть и твой сеанс.

Блок 14

Службы, журналы и обновления

Учимся наблюдать перед изменениями.

Прочитать состояние

Служба может иметь тип запуска Automatic, но быть сейчас Stopped. И наоборот, Manual-служба может работать после запуска по триггеру. Окно Services показывает состояние, тип запуска, учётку входа и зависимости. Состояние Running ещё не означает, что приложение отвечает правильно.

Get-Service DNS, DHCP, Netlogon
Get-WinEvent -FilterHashtable @{LogName='System'; Level=2; StartTime=(Get-Date).AddDays(-1)} -MaxEvents 30
Get-Volume | Select-Object DriveLetter, SizeRemaining, Size
Get-ScheduledTask | Select-Object TaskName, State

Первую команду запускай на сервере с этими ролями; отсутствие DHCP на FS1 нормально. Вторая читает ошибки System за последние сутки. Get-ScheduledTask показывает задачи, но не доказывает успешный последний запуск; у нужной задачи дополнительно смотри History, Last Run Time, Last Task Result или Get-ScheduledTaskInfo.

Искать в журнале

  1. Открой eventvwr.msc → Windows Logs → System и Application. Для роли смотри также Applications and Services Logs, например DNS Server, GroupPolicy/Operational.
  2. Отфильтруй время наблюдаемой ошибки, источник и Event ID. Не объявляй любую красную запись причиной сегодняшнего сбоя.
  3. Сопоставь соседние события, реальный симптом, изменение настроек и время на клиентах. Сохрани нужный журнал/событие в диагностический каталог, если нужно передать доказательство.
  4. Перед рестартом службы посмотри зависимости и влияние на пользователей. Перезапуск DNS на единственном DC, файлового сервиса или рабочей БД — действие с последствиями.

Обновления

Сначала проверь резервную копию, свободное место, совместимость приложения и окно обслуживания. Установи обновления через предусмотренный организацией канал, контролируй необходимость перезагрузки. После неё проверь роли, сетевой вход обычного пользователя, приложение и backup. Номер установленного обновления и факт перезагрузки важнее обещания «всё актуально» без источника.

Get-HotFix полезен как часть инвентаризации, но не перечисляет абсолютно все варианты обновлений и не доказывает отсутствие уязвимостей. WSUS встречается в существующих средах; выбор нового средства обновлений и его жизненный цикл проверяют отдельно, не строя учебную лабораторию на предположении о вечном развитии продукта.

Автоматизация без скрытых полномочий

В Task Scheduler → Create Task задают учётку выполнения, trigger, action, условия и журнал. «Run with highest privileges» не превращает непривилегированную учётку в администратора, а может запускать уже разрешённый повышенный контекст. Учитывай рабочий каталог, абсолютные пути, код возврата, доступ к сетевым ресурсам и безопасное хранение секретов. Службы и задания не должны использовать личный пароль уволившегося сотрудника.

Перед каждым изменением запиши: что меняешь, зачем, исходное значение, окно, как проверить результат и как вернуться. Один контролируемый шаг даёт больше понятной информации, чем одновременно перезагрузить всё и поменять DNS, firewall и драйвер.

Принтер, сайт и удалённые рабочие столы

Три разные дополнительные задачи сервера.

Общий принтер

Разворачивай на выделенном рядовом сервере по необходимости, не добавляй Print Spooler на контроллер «на всякий случай». Нужны сетевой адрес принтера, поддерживаемый подписанный драйвер производителя и политика его распространения.

  1. Добавь Print and Document Services → Print Server. Открой Tools → Print Management (printmanagement.msc).
  2. Print Servers → нужный сервер → Printers → Add Printer. Создай Standard TCP/IP Port по реальному адресу принтера, выбери подходящий драйвер, имя очереди и имя публикации.
  3. Во вкладке Security разреши нужной группе Print; Manage Documents и Manage Printers оставь операторам по задаче.
  4. На клиенте подключи \\сервер-печати\имя-очереди, учти требования доверенного развёртывания драйвера/Point and Print. Не снимай защитные ограничения ради скрытия запроса администратора.
  5. Напечатай тестовую страницу именно с клиентского ПК, проверь очередь и фактический выход на нужном устройстве.

Резерв DHCP закрепляет адрес, но не создаёт очередь. Успешный ping принтера не доказывает печать, состояние картриджа и правильность драйвера. В нашей виртуальной лаборатории физический принтер не создаётся, поэтому реальный лист остаётся отдельной проверкой.

Простой учебный сайт IIS

На отдельном рядовом сервере с чистой тестовой конфигурацией:

Install-WindowsFeature Web-Server -IncludeManagementTools
Get-Service W3SVC

Открой Tools → Internet Information Services (IIS) Manager, Sites. На типовой новой установке проверь Default Web Site, binding и его physical path. В браузере самого сервера http://localhost обычно показывает стартовую страницу. Для собственного сайта создай отдельный каталог, Site, application pool и binding; если порт/имя уже заняты, не удаляй чужой сайт. Пути и права выдаются учётке соответствующего пула, а не Everyone Full Control.

С PC1 проверь имя DNS → TCP 80 для учебного HTTP → HTTP-ответ → содержимое. Для реальной публикации потребуются HTTPS, сертификат с нужным именем, обновление, защита приложения и план публикации. DNS-запись сама не создаёт binding IIS; порт 443 без правильно работающего TLS и сайта — неполная проверка.

RDS: рабочие столы сотрудников

RDP для двух административных сеансов и Remote Desktop Services — разные сценарии. Для рабочей RDS-среды проектируют Session Host, Connection Broker, Web Access/Gateway по задаче, сервер лицензирования, RDS CAL нужного режима и версии, профили, ресурсы и доступ. Дополнительные обычные Windows Server CAL могут также требоваться по условиям лицензирования.

RDS-развёртывание начинают через Add Roles and Features → Remote Desktop Services installation при выполненных требованиях. Это не универсальная инструкция «поставить одну роль на DC». Приложения должны поддерживать многопользовательскую работу и своё лицензирование; пользовательские профили и файлы нужно резервировать. Нужны фактический вход нескольких обычных пользователей, изоляция данных и проверка работы лицензирования. Пробный период не является постоянным решением.

Службы сертификатов AD CS, отказоустойчивые кластеры и миграция старых доменов — отдельные проекты. AD CS создаёт инфраструктуру доверия и не требуется просто для добавления пользователя или папки; его не устанавливают без плана защиты ключей и восстановления.

Блок 16

Hyper-V и границы виртуальных машин

Различаем хост, гостя, сеть и снимки.

Когда нужен Hyper-V

Hyper-V запускает виртуальные машины на поддерживаемом хосте. Для установки проверяют процессорную виртуализацию, SLAT, аппаратные и программные требования и совместимость уже установленных средств виртуализации. В этом курсе установка Hyper-V на твой компьютер не выполняется: если VMware уже есть, можно продолжать там. Совместное использование гипервизоров и nested virtualization зависит от версии и конфигурации.

Если Hyper-V разворачивают на отдельном согласованном Windows Server-хосте, роль добавляют через Add Roles and Features → Hyper-V. PowerShell Install-WindowsFeature Hyper-V -IncludeManagementTools -Restart устанавливает роль и может сразу перезагрузить хост. Это не команда для запуска внутри любого DC1 или на рабочем ПК без подготовки. На клиентской Windows используют другой механизм компонентов.

Три вида коммутатора

External связывает ВМ с внешней сетью через адаптер хоста. Internal связывает ВМ между собой и с хостом. Private связывает ВМ только между собой. Наличие Internal само по себе не создаёт NAT, шлюз и DHCP. Для основной лаборатории подходит Private.

  1. Hyper-V Manager → Virtual Switch Manager → New virtual network switch → Private, имя Lab-Only.
  2. New → Virtual Machine: имя, путь, поколение по требованиям гостевой ОС, память, подключение Lab-Only, новый виртуальный диск и официальный ISO.
  3. Для современных гостевых систем обычно рассматривают Generation 2; у Windows 11 отдельно проверяют TPM/Secure Boot и остальные требования.
  4. Создай DC1, FS1 и PC1, подключив их к одному Lab-Only. Назначение IPv4 внутри гостя делается уже в гостевой Windows.

Checkpoint и backup

Checkpoint хранит состояние для возврата по правилам гипервизора; production checkpoint использует поддерживаемые механизмы согласованности. Это не отдельная защищённая копия на другой площадке. Долгие цепочки растут и осложняют хранение. Не удаляй файлы AVHDX/VHDX или VMDK/delta вручную, чтобы освободить место: используй штатные операции с проверенной копией.

При одном физическом хосте отказ этого хоста может остановить сразу DC1, FS1 и PC1. Две ВМ на одном диске не становятся двумя независимыми площадками. Планируй резервирование питания, хранения, гипервизора и копий в зависимости от допустимого простоя.

Что проверять

На гипервизоре — состояние ВМ, свободную память/CPU/диск, тип коммутатора, checkpoints и backup. В госте — сеть, службы, события и данные. Запущенная ВМ не равна работающему домену. Открытая консоль гипервизора не доказывает доступ по RDP.

Клонирование подготовленного доменного компьютера или контроллера требует поддерживаемого процесса; копирование файлов работающего DC в новую ВМ и запуск рядом не является безопасной инструкцией создания второго контроллера. Для лаборатории проще чистая установка и штатное добавление нового DC в существующий домен.

Поиск ошибок по слоям

Не меняем всё сразу: устанавливаем, на каком шаге ломается сценарий.

Сотрудник не открывает общую папку

Сначала запиши: кто, на каком компьютере, какой точный путь, какое время и текст ошибки. «Сеть не работает» слишком расплывчато. Работает ли другой ресурс и другой пользователь — полезное сравнение, но не повод менять всё сразу.

  1. Настройки клиента: ipconfig /all. Адрес из ожидаемой сети, маска, DNS на DC1. 169.254.x.x направляет к DHCP/сегменту, но причину ещё нужно подтвердить.
  2. Имя: Resolve-DnsName FS1.ad.example.test. Проверяй, что ответ относится именно к FS1.
  3. Нужный транспорт: Test-NetConnection FS1.ad.example.test -Port 445. Успешный ping недостаточен; выключенный ICMP не всегда мешает SMB.
  4. Кто вошёл: whoami, whoami /groups. Уточни локальную/доменную учётку и обновлялось ли членство новым входом.
  5. Публикация и права: на FS1 прочитай Get-SmbShare, Get-SmbShareAccess -Name Accounting, icacls D:\Shares\Accounting. Затем проверь Effective Access и конкретное действие под сотрудником.
  6. Фактическая операция: открыть, создать тестовый файл, изменить и удалить его — по необходимым правам. Чтение и запись не одно и то же.

Не удаётся доменный вход

Проверяй DNS/SRV и выбранный домен, время, состояние учётки и пароль, доступ к DC, ограничения входа и журналы. Вход по сохранённым доменным данным без доступного DC может сработать; это не доказательство текущей связи с каталогом. Ошибка trust relationship относится к доверительному каналу машины и требует проверки, а не автоматического сброса всех паролей.

Не применяется GPO

Объект в нужной OU? GPO привязана и включена? Нужная часть User/Computer? Подходят фильтры? Доступны DNS, DC и SYSVOL? Что в gpresult /r и GroupPolicy/Operational? Некоторые настройки требуют нового входа или перезагрузки. Команда gpupdate сама не переносит объект в OU.

Недоступен RDP

Маршрут и адрес → TCP 3389 → служба/правила/NLA → аутентификация → право входа → сеанс. Успешный TCP-тест не означает успешный RDP-вход. Членство в домене также не создаёт маршрут из любой сети.

Как записать результат честно

«Подтверждено: имя разрешилось в 192.168.50.20, TCP 445 доступен. Не подтверждено: разрешение записи. Следующий шаг: проверить группы и ACL под Анной». Такая запись полезнее общего PASS. Отсутствие ошибки в одном журнале не доказывает исправность всей системы.

После исправления повтори исходный сценарий и контрольный отрицательный пример: разрешённый сотрудник проходит, посторонний не получает лишний доступ. Изменяй одну связанную причину за раз и сохраняй исходные значения для возврата.

Блок 18

Рабочие задачи: принять, перевести, отключить

Собираем всё в повторяемый порядок.

Новый сотрудник

  1. Получи подтверждённую заявку: ФИО, подразделение, руководитель, дата начала и необходимые ресурсы. Права копируют по роли, а не слепо со «всего как у директора».
  2. Создай уникальную учётку в нужной OU, временный пароль со сменой и принятый способ его передачи. Почта, VPN и прикладные сервисы могут требовать отдельного создания.
  3. Добавь согласованные группы отдела и доступа; административные группы — только по отдельной задаче.
  4. Подготовь PC1: обновления, защита, имя, внутренний DNS, ввод в домен, правильная OU и настройки GPO.
  5. Вместе с сотрудником проверь вход, нужные папки, запись, принтер и приложения. Отдельно проверь отсутствие доступа к чужому отделу.
  6. Зафиксируй выданные ресурсы и процедуру обращения при ошибках. Не записывай его постоянный пароль в журнал.

Перевод в другой отдел

Меняются группы доступа и, если нужно, OU/политики. Прежние права убирают по заявке, новые добавляют по роли. Учитывай вложенные группы и отдельные приложения. После полного нового входа проверь оба направления: новый ресурс доступен, старый лишний — уже нет. Изменение OU и членства — две разные операции.

Увольнение или компрометация

По утверждённой процедуре отключи доменную учётку, обработай VPN/почту/облако/приложения, активные сеансы, токены и выданные ключи. Простое Disable-ADAccount не гарантирует мгновенного завершения всех существующих SMB/RDP/облачных сессий и аннулирования всех билетов. Для срочного инцидента нужен отдельный согласованный план сдерживания.

Данные передают и сохраняют по политике, доступы отзывают, сроки удаления соблюдают. Учётку и профиль не стирают сразу вместе с единственными документами. Если пароль использовался в службах или заданиях — исправь эту зависимость штатно и проверь работу, не включай старую учётку навсегда ради «чтобы не падало».

Ежедневно и периодически

Ежедневно: свежесть и результат резервных копий, место на томах и гипервизоре, критические службы, ошибки задач и важные оповещения. В окно обслуживания: обновления и перезагрузки с контрольными сценариями. Периодически: восстановление из копии, лишние привилегии, неиспользуемые учётки, срок сертификатов и лицензий, контакты и документация. Частота зависит от требований системы и риска.

Финальная лабораторная работа

Анна входит на PC1 как LAB\anna; DNS и DHCP соответствуют схеме; PC1 в нужной OU; GPO подтверждена отчётом и экраном; \\FS1\Accounting даёт Анне нужные операции, а постороннему не даёт лишнего; тестовый файл восстановлен из копии в отдельный каталог. Для каждого пункта укажи реальное доказательство. Анимация и тесты этого учебника не подтверждают, что всё уже сделано на твоих ВМ.

Куда идти дальше

Второй DC и репликация, делегирование, LAPS/gMSA, развитые GPO, централизованные обновления и журналы, полноценная модель резервирования, RDS, PKI и миграция устаревших серверов. Эти темы изучают на отдельной лаборатории после уверенного входа, DNS, групп и прав.

Старые Server 2008 R2/2012 R2 и рабочие домены не обновляют «как свежую песочницу». Для миграции собирают зависимости, состояние AD/DNS/репликации, совместимость, backup и план переключения. Удаление роли, перенос FSMO и понижение старого DC требуют отдельного проверяемого маршрута.

Словарь простыми словами

Роль

Набор серверных возможностей для определённой задачи. Например, DHCP Server.

Служба

Программа, которая работает в фоне и обслуживает запросы независимо от окна управления.

Оснастка

Окно управления конкретной системой: ADUC, DNS Manager и другие.

AD DS

Доменная служба каталога: общий список пользователей, компьютеров и групп с их свойствами.

Домен

Область AD с общими учётными записями и правилами. Не равна имени сайта.

DC

Domain Controller — контроллер домена, сервер с каталогом AD.

Лес

Верхняя структура Active Directory. В нашем примере содержит один домен.

OU

Организационная единица: контейнер для объектов, делегирования и привязки политик. Не группа доступа.

Группа безопасности

Список учётных записей или других групп для назначения разрешений.

AGDLP

Учётки → глобальная группа роли → локальная группа домена → разрешение на ресурс.

UPN

Имя входа вида anna@ad.example.test. Почтовый ящик не создаёт.

DNS

Система поиска адресов и служб по именам. В AD помогает найти контроллер домена.

A / AAAA

DNS-записи имени для IPv4 / IPv6.

SRV

DNS-запись о службе, например где искать контроллер домена.

Forwarder

DNS-сервер, которому внутренний DNS пересылает подходящие запросы.

DHCP

Служба автоматической выдачи клиентам адресов и других сетевых настроек.

Область DHCP

Scope: пул адресов и его параметры для определённой подсети.

Аренда

Lease: адрес выдан клиенту на ограниченный срок.

Резервирование

Закрепление DHCP-адреса за идентификатором конкретного клиента.

Шлюз

Реальный маршрутизатор для доступа в другие сети. В основной лаборатории отсутствует.

SMB

Протокол доступа к общим файлам и ряду других ресурсов Windows.

NTFS

Файловая система Windows с разрешениями, наследованием и другими возможностями.

ACL

Список записей, задающих разрешения и запреты для объекта.

Наследование

Получение вложенной папкой разрешений от родительской по правилам ACL.

Modify

Типовое разрешение изменения файлов, обычно включая удаление. Не равно только записи.

GPO

Объект групповой политики с настройками компьютеров и пользователей.

Link

Привязка GPO к сайту, домену или OU; не копия самой политики.

SYSVOL

Публикуемая контроллерами область, где хранятся в том числе файлы доменных политик.

Kerberos

Механизм доменной аутентификации с билетами. Зависит в том числе от корректного времени.

DSRM

Режим восстановления служб каталога и отдельный пароль для такого восстановления.

RDP

Протокол удалённого рабочего стола. Открытый порт не равен успешному входу.

RDS

Набор служб для удалённых пользовательских рабочих столов и приложений.

CAL

Клиентская лицензия доступа по условиям продукта. RDS CAL — отдельная позиция.

NLA

Предварительная сетевая аутентификация RDP; поддерживает защиту удалённого входа.

RSAT

Средства удалённого администрирования с административного компьютера.

LAPS

Средства управления уникальными локальными административными паролями и правами доступа к ним.

gMSA

Управляемая доменная служебная учётная запись для поддерживаемых приложений.

VSS

Механизм согласованных снимков Windows; результат зависит от поддержки приложением и backup-продуктом.

RPO

Допустимый объём потери последних изменений, выраженный временем.

RTO

Допустимое время восстановления работы после сбоя.

System State

Набор состояния системы для поддерживаемого восстановления; особенно важен для AD.

Checkpoint

Снимок состояния ВМ по правилам гипервизора. Сам по себе не отдельная защищённая резервная копия.

Хост / гость

Хост запускает гипервизор; гость — операционная система внутри ВМ.

IIS

Веб-сервер Windows: сайты, привязки, пулы приложений и обработка HTTP/HTTPS.

Binding

Привязка сайта IIS: сочетание адреса, порта, имени и настроек протокола.

FSMO

Особые роли контроллеров AD. Их перенос планируют при миграции и восстановлении.
